Inside the Seek Loop - Timestamps, Fallback, and Hallucination Guards in SYSTRAN/faster-whisper

19 Oct 2026  ·  9 mins read

Contents

Our first walk of SYSTRAN/faster-whisper introduced the cast: WhisperModel, the batched wrapper, PyAV audio, the Silero VAD, and the claim that a reimplementation on CTranslate2 makes the same model four times faster. What that tour did not open up is transcribe.py’s engine room — the eighteen hundred lines where the actual decoding decisions live. Whisper’s own implementation is famously a pile of heuristics: a seek pointer that sometimes advances and sometimes retries, three separate tests for whether a decoded window can be trusted, a prompt manager that keeps context coherent across windows, and a timestamp alignment scheme that reads cross-attention maps. faster-whisper rebuilds every one of those heuristics in Python over CTranslate2’s primitives, and reading them is a masterclass in production speech recognition. As always, this is an educational read of published source on the master branch, MIT-licensed; the first post covers the module map we now zoom past.

The one-sentence summary: generate_segments is a clock, generate_with_fallback is a skeptic, and the VAD is the map that tells both where speech actually is. Everything else in the package exists to feed, verify, or measure that trio.

Overview of the decoding machinery: the package surface hands audio through the VAD into WhisperModel, whose seek loop and fallback logic drive CTranslate2; the batched wrapper reuses the same pieces over merged chunks, while benchmarks, tests, and the Docker entry measure and package it all.

Reading the overview from left to right:

  • transcribe.py holds the whole engine: WhisperModel with its public transcribe at line 781.
  • The seek loop is generate_segments, and its clip arithmetic starts at line 1176.
  • generate_with_fallback decides whether a window’s output can be trusted.
  • add_word_timestamps rebuilds word timing from the align call at line 1746.
  • The batched wrapper is the batched sibling, with its own transcribe at line 254.
  • vad.py supplies get_speech_timestamps and collect_chunks at 220.
  • audio.py decodes any container through PyAV with decode_audio and pad_or_trim at 117.
  • utils.py fetches converted checkpoints via download_model and formats timestamps at line 118.
  • speed_benchmark.py measures real-time factor with measure_speed; wer_benchmark.py scores accuracy.

The seek loop: windows, clips, and silence

The public transcribe builds the option dataclasses — TranscriptionOptions at line 71 carries every knob — and then hands you a generator, which is where generate_segments begins. Its unit of work is the thirty-second window. Without a VAD, the seek pointer marches through the file in 30-second steps; with one, the loop first asks get_speech_timestamps for speech regions and converts them into seek clips, so the pointer jumps from speech to speech and silence never reaches the model. The per-window bookkeeping is precise: time_offset at line 1205 converts the seek index into seconds via the feature extractor’s per-frame time, the mel features are sliced to the window, and everything decoded is stamped relative to that offset. After a window is accepted, the seek advances past the last timestamp token rather than the full window — the original Whisper’s trick for not losing audio between timestamp boundaries.

The most interesting branch is the hallucination guard. Whisper’s known failure mode is inventing fluent text over silence or music — famously “Thank you for watching” loops. When hallucination_silence_threshold is set and a segment looks suspicious, the code at lines 1327 through 1369 uses the word timestamps to find where speech actually resumed, truncates the seek to the last real word end, and re-decodes just the silence-free remainder. Note the dependency: the guard needs word timestamps to work, which is why the option is disabled by default and why the docstring ties the two together. The VAD path also patches timestamps back into wall-clock positions through SpeechTimestampsMap, because chunks were removed and re-ordered and every segment’s reported time must land in the original audio’s frame of reference.

generate_with_fallback: deciding a window is wrong

generate_with_fallback is the skeptic that sits between the encoder and your transcript. It samples with the first temperature, then runs three tests on the result. The first is repetitiveness: get_compression_ratio at line 1924 zlib-compresses the text, and if the ratio above the threshold says the output is too repetitive, needs_fallback is set at line 1520. The second is confidence: if the average log probability at line 1533 falls under log_prob_threshold, the window is rejected. The third is the clever one — if there is no speech in the window at all, the low-probability result is explicitly accepted at line 1550, because “silence” is a correct answer for silence, and punishing it would cause the fallback loop to hallucinate something to say. On failure, the temperature climbs — up to len(temperatures) retries, each with best_of sampling at line 1473 — and the best surviving candidate wins. Before any of this runs, get_suppressed_tokens at line 1929 assembles the suppression list: non-speech tokens, user-supplied suppressions, and the compression-ratio flagged set. The prompt machinery at line 1569 closes the loop across windows, extending the previous window’s text so the model keeps its style and vocabulary — sot_sequence and task tokens included.

Word timestamps: alignment from CTranslate2

Word timestamps in this codebase are not heuristic guesswork — they are cross-attention arithmetic delegated to CTranslate2. add_word_timestamps at line 1604 collects the text tokens per segment and calls find_alignment at line 1735, which invokes model.align at line 1746 — CTranslate2 runs the DTW over cross-attention maps with a median filter, and returns token-to-frame alignments plus per-token probabilities. The Python side then does the cleanup Whisper’s original is known for: a median-based duration cap at lines 1630 through 1653 truncates impossible word lengths at sentence boundaries, merge_punctuations at line 1955 glues punctuation back onto neighbors, and the tokenizer’s split_to_word_tokens handles scripts where words do not split on spaces — CJK among them. The same alignment data feeds the timestamp-based splitter at line 1061, which cuts long segments at reliable timestamp tokens when multilingual subtitles demand it, and detect_language at line 1811 reuses the encoder output for its language-likelihood pass.

The batched sibling and the VAD that feeds it

The speed story closes with the batched wrapper class at line 111. Its transcribe at line 254 asks the VAD for speech regions, then collect_chunks at line 220 reassembles them into batch_size windows of 30 seconds each — padding partial chunks — and forward at line 119 runs one CTranslate2 batch over all of them. Per-window decoding inside the batch is generate_segment_batched at line 174, which skips the fallback machinery for speed and returns logits-level results that the wrapper scores and trims at line 246. The results finally stream through _batched_segments_generator at line 582, where chunk offsets are restored to original-audio time — the same restore_speech_timestamps helper at line 1889 the non-batched path uses. The trade the README’s seventeen-seconds benchmark makes is now legible: batching and VAD pruning replace the fallback skeptic with a cheaper pass, and the Silero model itself at line 330 runs as a bundled ONNX file — the same runtime-engine pattern ONNX Runtime standardized, applied to a 2-megabyte gatekeeper.

Two support modules deserve their paragraph because both are quieter than they look. The feature extractor computes log-Mel spectrograms, and _get_feature_kwargs at line 763 quietly checks the model directory for a preprocessor config so that older converted checkpoints keep their original mel parameters instead of silently drifting — a two-line guard against one of the nastiest classes of silent accuracy bugs. The tokenizer wraps Hugging Face’s tokenizers library with Whisper’s task and language token bookkeeping, and its word-splitting logic is what makes CJK and mixed-script timestamps work at all. Around the package, the Docker entry point wires a wav file to a model with nothing but environment variables, and test_utils.py covers the download layer — including the resume-from-partial-download behavior that anyone on hotel Wi-Fi will eventually thank.

From Install to Your First Model

Everything above activates through arguments to transcribe(): vad_filter=True arms the VAD path, word_timestamps=True enables the alignment machinery, and hallucination_silence_threshold (a float in seconds) arms the guard — which requires word timestamps. The benchmark directory is the honest way to see the trade-offs: speed_benchmark.py sweeps model sizes and batch settings, memory_benchmark.py tracks peak memory per compute type, and wer_benchmark.py scores the accuracy cost of batching, with shared dataset helpers behind them.

Honest limits: this walk stayed in Python; the actual Transformer math is CTranslate2’s, and its align internals are a separate engine we did not read. The hallucination guard’s thresholds are heuristics tuned on English-ish audio — other languages may need different values, and the code itself warns that the timestamp trick assumes VAD quality. We read, not measured: the README’s numbers come from the benchmark files, not from us. And the fallback logic is deliberately conservative — turning all three guards off is a legitimate speed choice for clean single-speaker audio, as the tests in test_transcribe.py demonstrate with real fixtures. For context in this series: vLLM and SGLang batch text tokens across users, LocalAI and xorbitsai/inference wrap speech models behind the same server walls as LLMs, and OpenVINO quantizes the same Whisper architecture for CPU. faster-whisper’s lesson — guard the clock, trust the alignment, batch only what the VAD proves is speech — is the most transferable of the lot.
