Every retrieval system has a generation model that gets the applause and an embedding model that does the work, and the embedding side is exactly where huggingface/text-embeddings-inference lives. TEI — as everyone calls it — is a Rust server whose entire purpose is to turn text into vectors, vectors into similarity scores, and query-document pairs into reranking scores, at throughputs that made it the default backing store for Hugging Face's own inference endpoints. Unlike the general-purpose serving engines this series has toured, from [vLLM](/vllm-2/) to [SGLang](/sglang-3/) to the ragged engine of [DeepSpeed](/deepspeed-2/), TEI narrows its ambition to a small set of request shapes and then optimizes them without mercy: it holds no chat templates, samples nothing, and generates nothing beyond a fixed pool of tokens. That narrowness is what makes its source so readable — two crates of Rust, one candle-based backend, and a model zoo that reimplements fourteen architectures without a single line of PyTorch. As always, this is an educational tour of published source on the main branch, Hugging Face's own license, and readers wanting the generation-side counterpart can compare [text-generation-inference](/inference/).

The one-sentence summary: an axum router translates five API dialects into calls on [Infer](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/infer.rs#L13), Infer orchestrates a tokenization pool, a [Queue](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/queue.rs#L36), and a blocking backend call, and the backend is [CandleBackend](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/lib.rs#L156), a dispatch table over hand-written model implementations that end in CUDA flash attention.

## One router, every protocol

The router's first trick is breadth: a single process speaks the dialects of half the embedding industry. The core routes are native — [embed](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/server.rs#L584) for pooled or sparse vectors, [rerank](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/server.rs#L305) for cross-encoder scoring, [predict](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/server.rs#L104) for classification labels, and [similarity](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/server.rs#L498), which is a two-vector cosine computed server-side. Around them sit the compatibility shims that made adoption frictionless: [openai_embed](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/server.rs#L1127) serves the `/v1/embeddings` shape so OpenAI-SDK clients work unmodified, and [vertex_compatibility](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/server.rs#L1532) covers Google's contract, with the route table showing the wiring plainly. There are also [tokenize and decode](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/server.rs#L1347) debug endpoints that expose the raw tokenizer, and a metrics route feeding Prometheus. Behind HTTP there is an alternative transport — a tonic [gRPC server](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/grpc/server.rs#L1370) sharing the same Infer facade — and the server code even carries conditional rewrites for SageMaker and Vertex deployment conventions, remapping `/` and `/invocations` to the right handlers. The design point worth stealing: the protocol layer is deliberately thin, and every route funnels into the same three facade verbs, so adding a dialect costs a struct and a handler, not a new runtime.

## The batch machine

The core crate is a compact lesson in Rust async architecture. Requests arrive as futures, and the first stop is admission control: [try_acquire_permit](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/infer.rs#L94) draws from a semaphore sized by max concurrent requests, so overload degrades to queueing at the door instead of memory pressure inside. Tokenization never blocks the async runtime because it runs in a dedicated pool — [Tokenization::new](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/tokenization.rs#L30) spins worker threads whose count defaults to one less than the machine's core count, and the [run() wiring](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/lib.rs#L237) makes that default explicit and tunable. Encoded requests become [Entry values](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/queue.rs#L12) appended to the Queue, and the whole batching policy is one function: [next_batch](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/queue.rs#L79) waits for at least one entry, then drains up to the model's batch capacity without padding concerns — sequences ride through the whole flow with their true lengths. Two spawned tasks close the loop: [batching_task](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/infer.rs#L525) pulls NextBatches and sends them down a channel, while [backend_task](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/infer.rs#L547) receives them and issues the actual model call through `spawn_blocking`, because candle's synchronous execution would otherwise stall the async reactor. Responses return through per-request oneshot channels, and the facade computes its own metrics — [InferMetadata](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/infer.rs#L628) carries tokenization and queue timings for the Prometheus histograms. It is the same producer-consumer shape this series found in [faster-whisper's](/faster-whisper-2/) generator loop and ONNX Runtime's thread pools, expressed in twenty lines of channels and semaphores.

## The candle backend and its model zoo

Candle is Hugging Face's minimal tensor framework, and TEI's backend crate is effectively a candle showcase. [CandleBackend::new](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/lib.rs#L163) inspects the model type and configuration, then builds exactly one architecture object; the [Backend impl](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/lib.rs#L639) reports [max_batch_size at line 640](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/lib.rs#L640) — the flash variants advertise no limit because they never pad — and dispatches embed and predict calls into the zoo. The zoo itself is the [Model trait](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/mod.rs#L104): implement `is_padded`, `embed`, and optionally `predict`, and you are in the family. BERT is the reference implementation to read first: [BertEmbeddings at line 42](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/bert.rs#L42) handles tokens and positions, [BertAttention at line 117](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/bert.rs#L117) carries the query-key-value projection with either absolute or rotary position treatment, [BertEncoder at line 340](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/bert.rs#L340) stacks the layers, and the heads make one model serve three businesses — a classification head for predict, a SPLADE head at [line 468](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/bert.rs#L468) for sparse retrieval, and plain pooling for dense embeddings. The rest of the zoo reads as a curriculum in embedding architecture: [ModernBertModel](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/modernbert.rs#L459) with its alternating attention and every-fourth-layer norm scheme, [DistilBertModel](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/distilbert.rs#L728) as the distilled student, [GTEModel](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/gte.rs#L712) adding a dense projection for Matryoshka-style truncation, [MPNetModel](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/mpnet.rs#L684) with disentangled position attention, [NomicBertModel](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/nomic.rs#L979) for long contexts, and [Qwen3Model](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/qwen3.rs#L747) showing that decoder-style LLMs now double as embedders, bringing rotary layers from [the shared rotary module](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/layers/rotary.rs#L99) and [RMSNorm](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/layers/rms_norm.rs#L5) with them. Shared plumbing — [Linear](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/layers/linear.rs#L32), [LayerNorm](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/layers/layer_norm.rs#L83), and a [cublasLt wrapper](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/layers/cublaslt.rs#L42) that fuses GEMM with bias and activation epilogues — keeps every model file short.

## CUDA realities: compute caps and honest limits

The GPU path is where TEI stops being portable and starts being fast. [flash_attn_varlen](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/flash_attn.rs#L23) is the gatekeeper: it reads the runtime compute capability once, and the dispatch at [lines 39 through 115](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/flash_attn.rs#L39) routes Turing's 7.5 to flash attention v1 with its no-ALiBi, no-windowing caveats, while everything from Ampere 8.0 through Blackwell calls the windowed v2 kernel, with and without ALiBi slopes. The varlen in the name matters: because the batching layer passes true sequence lengths instead of padded ones, the kernel processes exactly the tokens that exist, which is why the flash model variants can advertise unbounded batch sizes. CUDA-only feature flags gate all of this — build without the feature and the code fails loudly rather than silently degrading to slow paths, a decision that shows up repeatedly in [FlashBertModel](https://github.com/huggingface/text-embeddings-inference/blob/main/backends/candle/src/models/flash_bert.rs#L217), the fused CUDA rewrite of the BERT forward that skips the vanilla module's intermediate tensors. Be honest about the boundaries: TEI serves one model per process, scales by running more containers, has no multi-GPU tensor parallelism, and will not chat — the gRPC and HTTP surfaces are strictly embed, rerank, predict, and similarity. That is the same trade the whole series keeps meeting, from [ExecuTorch's](/executorch/) mobile constraints to [Triton's](/triton-2/) kernel specialization: narrow the surface, then make the narrow thing as fast as the hardware allows.

## From Install to Your First Model

The fastest route is Docker: `docker run --gpus all -p 8080:80 -v /data:/data ghcr.io/huggingface/text-embeddings-inference:1.8 --model-id BAAI/bge-base-en-v1.5`, and the server comes up already warm, having fetched weights through [download_artifacts](https://github.com/huggingface/text-embeddings-inference/blob/main/core/src/download.rs#L40) on first use. Then `curl :8080/embed -d '{"inputs":"the quiet workhorse"}'` returns your first vector, `:8080/rerank` scores a query against candidates, and `:8080/v1/embeddings` answers an OpenAI-format client without it knowing the difference. The fine print is worth reading in the source rather than the README: pooling strategy is inferred from the model's config but can be forced, the char-limit truncation in the tokenization pool quietly protects the queue from pathological inputs, and the memory floor is real — a 7 billion parameter embedder like Qwen3 needs a GPU with room to spare, while BERT-class models fit comfortably on modest cards. Where it fits, though, it is the shortest path from model name to production vectors we have measured. Pair this tour with the training-side machinery of [ONNX Runtime's](/onnxruntime-2/) execution plans, the speech sibling [faster-whisper](/faster-whisper-2/), the LLM-serving counterparts [lmdeploy](/lmdeploy-2/) and [MLC](/mlc-llm-2/), and the local stack at [LocalAI](/localai/) — the pattern repeats everywhere: production inference is a queue, a batcher, and a kernel, wearing a competent HTTP face.
