Most vector databases grew out of an ANN index and added a database around it. Weaviate grew out of a database and added the vectors in. The result shows everywhere in the source: writes flow through a write-ahead-logged LSM tree that Weaviate implements itself, from memtable to immutable segment to background compaction; deletes are real tombstones that keep both the object store and the HNSW graph consistent; and queries are database queries — filters, sorts, aggregations, tenancy rules — where vector similarity is one capability among several rather than the whole product. Hybrid search fuses dense embeddings with BM25 keyword scoring under a single alpha parameter, rerankers reshuffle the fused results through cross-encoders, and modules bring the vectorizers of OpenAI, Cohere, Hugging Face, Ollama, and dozens of others into the process. It runs as a single binary or a Kubernetes cluster, scales per-collection with consistent-hash sharding, and keeps tenants isolated down to per-shard directories for the multitenant SaaS pattern that most vector stores bolt on later, if at all.

The codebase is Go, organized in a clean three-ring layout: `adapters` holds the REST and gRPC servers plus the storage engines, `usecases` holds the domain logic — schema, sharding, replication, the query explorer — and `entities` holds the shared types and the module capability interfaces. The heart is `adapters/repos/db`, where the four-and-a-half-thousand-line `index.go` owns one collection, each shard pairs the LSM key-value store with an inverted index and an HNSW graph, and the graph itself is maintained like database state — with its own commit log, asynchronous neighbor repair, and quantized variants of every distance kernel. Add the roaring-bitmap filter sets and the raft-backed schema log, and you have one of the most complete storage-engine educations in the open source AI stack. As always in this series, what follows is an educational tour of published source code.

Reading the overview from left to right:

- Every service is assembled in [the REST wiring](https://github.com/weaviate/weaviate/blob/main/adapters/handlers/rest/configure_api.go), the central constructor file.
- [The GraphQL handler](https://github.com/weaviate/weaviate/blob/main/adapters/handlers/graphql/schema.go) reflects your schema into queryable types.
- [The gRPC manager](https://github.com/weaviate/weaviate/blob/main/grpc/conn/manager.go) serves the versioned protocol modern clients use.
- [The schema manager](https://github.com/weaviate/weaviate/blob/main/usecases/schema/manager.go) applies collection changes as cluster-wide transactions.
- [The sharding state](https://github.com/weaviate/weaviate/blob/main/usecases/sharding/state.go) maps partitions and tenants onto nodes with consistent hashing.
- [The replica coordinator](https://github.com/weaviate/weaviate/blob/main/usecases/replica/coordinator.go) runs two-phase batch writes and quorum reads.
- [The explorer](https://github.com/weaviate/weaviate/blob/main/usecases/traverser/explorer.go) executes every query against per-shard search.
- [The HNSW index](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/hnsw/index.go) is the approximate nearest neighbor graph with database-grade durability.

## Why You Need This

The first reason is the storage engine, which is a complete LSM-tree implementation written for one purpose. [The bucket](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/lsmkv/bucket.go) — twenty-seven hundred lines — manages memtables, immutable flushes, secondary indexes, and write-ahead recovery, while [the segment format](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/lsmkv/segment.go) lays out the on-disk key-value files with block indexes and range iterators. Every object you insert, every inverted-index posting, every quantization table lives in these buckets, and [the compactor](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/compactor/compactor.go) merges segments in the background, dropping tombstones to reclaim space. Reading it teaches the LSM pattern end to end without the distraction of a general-purpose database — [the roaring-set structures](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/roaringset/binary_search_tree.go) show how bitmap ID sets become filter allow-lists and deny-lists, and [the inverted analyzer](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/inverted/analyzer.go) shows how text becomes the postings that power BM25.

The second reason is the HNSW implementation, which treats the ANN graph as durable state rather than a rebuildable cache. [The search](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/hnsw/search.go) — fifteen hundred lines — walks layers greedily with configurable ef, filtered by allow-lists so pre-filtering composes with the graph walk instead of fighting it. [Inserts](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/hnsw/insert.go) pick levels and neighbors heuristically, [neighbor maintenance](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/hnsw/neighbor_connections.go) repairs links asynchronously so deletes never strand the graph, and [deletes](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/hnsw/delete.go) tombstone nodes and re-connect orphans — the operations that separate a real vector index from a demo. Every mutation flows through [the commit logger](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/hnsw/commit_logger.go), so the graph survives crashes by replay, and [the vector cache](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/cache/cache.go) keeps hot vectors in memory so walks avoid disk. Around the graph: [the dynamic index](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/dynamic/index.go) that starts flat and promotes to HNSW automatically, and [the compression kernels](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/compressionhelpers/compression.go) with product and binary quantization plus SIMD distance functions.

The third reason is the distributed design, which solves the problems every vector database eventually faces. [The sharding state](https://github.com/weaviate/weaviate/blob/main/usecases/sharding/state.go) implements consistent hashing with per-collection shard counts and tenant-aware partitioning — the multitenancy story that lets a SaaS with ten thousand customers keep each customer's vectors in an isolated shard. [The replica coordinator](https://github.com/weaviate/weaviate/blob/main/usecases/replica/coordinator.go) and [the replica finder](https://github.com/weaviate/weaviate/blob/main/usecases/replica/finder.go) implement configurable consistency: two-phase batch writes across replicas, quorum reads, and repair flows when a node falls behind. Schema changes replicate through [the raft log](https://github.com/weaviate/weaviate/blob/main/cluster/log/logger.go) so every node agrees on the collection layout. And the extensibility is unmatched in the category: [the module capability interfaces](https://github.com/weaviate/weaviate/blob/main/entities/modulecapabilities/module.go) let external plugins provide vectorization ([text2vec-transformers](https://github.com/weaviate/weaviate/blob/main/modules/text2vec-transformers/module.go) is the reference), reranking ([reranker-transformers](https://github.com/weaviate/weaviate/blob/main/modules/reranker-transformers/module.go)), generative completion, and [S3 backups](https://github.com/weaviate/weaviate/blob/main/modules/backup-s3/client.go) — seventy modules in-tree, from OpenAI to Ollama.

Walking the detail diagram, one insert is traceable end to end. [The gRPC manager](https://github.com/weaviate/weaviate/blob/main/grpc/conn/manager.go) receives the batch through [the v1 protocol bindings](https://github.com/weaviate/weaviate/blob/main/grpc/generated/protocol/v1/weaviate.pb.go); [the replica coordinator](https://github.com/weaviate/weaviate/blob/main/usecases/replica/coordinator.go) resolves target hosts through [the finder](https://github.com/weaviate/weaviate/blob/main/usecases/replica/finder.go) and runs the two-phase write; [the collection index](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/index.go) fans out to the right shards per [the sharding state](https://github.com/weaviate/weaviate/blob/main/usecases/sharding/state.go); and [the shard](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/shard.go) writes the object into [the LSM bucket](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/lsmkv/bucket.go), the tokens into the inverted buckets, and the vector into [the HNSW graph](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/vector/hnsw/index.go) with its commit log. One query follows the mirror path: GraphQL or gRPC in, [the explorer](https://github.com/weaviate/weaviate/blob/main/usecases/traverser/explorer.go) consults modules to vectorize the query text, [hybrid search](https://github.com/weaviate/weaviate/blob/main/usecases/traverser/explorer_hybrid.go) fuses dense and BM25 results, [the boost scorer](https://github.com/weaviate/weaviate/blob/main/usecases/traverser/boost_scorer.go) re-weights by cross-references, and [the reranker module](https://github.com/weaviate/weaviate/blob/main/modules/reranker-transformers/module.go) gives a cross-encoder the final word before pagination.

The durability story composes the same parts. [Memtables flush](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/lsmkv/segment.go) into segments, [compaction](https://github.com/weaviate/weaviate/blob/main/adapters/repos/db/compactor/compactor.go) reclaims space, and [the backup module](https://github.com/weaviate/weaviate/blob/main/modules/backup-s3/client.go) streams consistent snapshots to object storage. The design lesson worth stealing: Weaviate never lets the fancy index outrun the boring storage — the LSM tree is the source of truth, the graph is derived state with its own log, and filters, tenancy, and consistency are first-class database features. That is why production teams pick it when embeddings become the operational core rather than an experiment, and why reading the source teaches real database engineering, not just vector math.

## From Install to Your First Collection

The quickest start is Docker: `docker run -p 8080:8080 -p 50051:50051 cr.weaviate.io/semitechnologies/weaviate:latest` exposes both the REST and gRPC ports, or `docker compose` with the bundled file enables modules like text2vec-transformers with their inference sidecars. With the Python client, three calls define everything: `client.collections.create("Article", vectorizer_config=wvc.configure.vectorizer.none())` for bring-your-own vectors or a module vectorizer, then `collection.data.insert({...})` per object, then `collection.query.near_text("a constitutional law case", limit=5)` or `collection.query.hybrid("constitutional law", alpha=0.5)` for fused search. Filters chain with `Filter.by_property("year").greater_than(2020)`, generative modules attach with `generate.single_prompt(...)`, and tenancy is one line: `multi_tenancy_config(enabled=True)` — tenants then live in isolated shards you enable per customer. Weaviate Embeddings, the managed variant, runs the same engine in the cloud when you outgrow self-hosting.

Honest limits: the Go binary is heavier than embedded options — it wants a container or a dedicated host, not a laptop import. The module architecture pulls inference sidecars per vectorizer, which multiplies Docker images and moving parts; managing your own vectors with the `none` vectorizer avoids the sprawl. HNSW builds are slower than flat brute force at small scale, and re-tuning ef, maxConnections, and compression settings is real engineering with measurable recall trade-offs. The dual license — BSD-3 for most code with the Weaviate License on some paths — requires reading before embedding it in a product. None of that changes the core verdict: if you want to learn how a production vector database actually works — from LSM segments to HNSW tombstones to raft schema logs — this is the most complete open source classroom available.
