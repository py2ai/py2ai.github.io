The fastest way to demo an LLM is a print loop; the fastest way to ship one is a chat interface people can actually use — with history, streaming, file uploads, authentication, and a thread they can return to. Chainlit is the framework that gives you all of it from a single Python file: decorate a function with `@cl.on_message`, send a reply with `cl.Message(...).send()`, run `chainlit run demo.py -w`, and a full React chat application appears in your browser, wired to your code over Socket.IO. The quickstart is genuinely two commands — `pip install chainlit` and `chainlit hello` — and the same surface grows with your application: steps that render agent reasoning as nested spans, elements that put images, audio, video, PDFs, and Pyplot figures inside the conversation, settings widgets, action buttons, and OAuth logins. Behind the simplicity sits real infrastructure: a FastAPI server, a websocket layer with session state, a pluggable data layer for threads and users, and instrumentation that turns LangChain, LlamaIndex, and OpenAI calls into visible steps automatically. Since May 2025 the project is community-maintained, with a formal maintainer agreement steering releases.

The repository is a monorepo with two citizens. The backend is a Python package whose public face — the `cl` module — is a two-hundred-line assembly of decorators and primitives, backed by a seventeen-hundred-line server, a typed configuration system, per-framework instrumentation modules, and a data layer with SQLAlchemy and DynamoDB implementations. The frontend is a React and Vite application with Zustand state management, built once at install time and served as static assets by the Python server. The two talk over a Socket.IO channel whose event names — message, step, element, settings — mirror the Python primitives exactly, which is what makes the backend code read like a specification of the UI. As always in this series, what follows is an educational tour of published source code.

Reading the overview from left to right:

- Everything you import lives in [the chainlit module](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/__init__.py), a two-hundred-line namespace assembly.
- [The CLI](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/cli/__init__.py) runs your script with watch mode and scaffolds new apps.
- [The FastAPI server](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/server.py) handles auth, static files, and project settings.
- [The socket layer](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/socket.py) is the bridge between browser events and your handlers.
- [Messages](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/message.py) carry `stream_token` for token-by-token replies.
- [Steps](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/step.py) render nested tool and agent traces.
- [Elements](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/element.py) are the media system — Image, Audio, Video, Pdf, Pyplot, TaskList.
- [The data layer](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/chainlit_data_layer.py) persists threads, steps, elements, and users.

## Why You Need This

The first reason is that the programming model is the right abstraction for chat applications. [The chainlit module](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/__init__.py) exports decorators — `on_message`, `on_chat_start`, `on_settings_update` — and primitives that map one-to-one onto what users see. [The Message class](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/message.py) does the hard streaming work: `stream_token` accumulates tokens, flushes at a computed cadence, and updates one UI bubble for the whole reply instead of spamming the socket. [The Step class](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/step.py) gives tool calls and intermediate reasoning a nested visual home — the `@cl.step(type="tool")` decorator turns any function into a traceable span — and [the Element hierarchy](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/element.py) covers every artifact an agent produces, from [plots](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/element.py) to [task lists](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/element.py). Underneath, [the context module](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/context.py) uses context variables so your handler code never touches a session ID, and [user_session](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/user_session.py) provides the per-user scratchpad every chatbot eventually needs.

The second reason is the transport and server layer, which is production-shaped rather than demo-shaped. [The server](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/server.py) at seventeen hundred lines carries the whole HTTP surface: OAuth logins through [a provider registry](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/oauth_providers.py) spanning Azure AD, GitHub, Google, Okta, and Keycloak, JWT and header authentication for programmatic access, element file upload and retrieval, project settings endpoints, and the static serving of the built frontend. [The socket module](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/socket.py) authenticates each websocket connection from its cookie or token, restores sessions across reconnects, and routes the `window_message` event into your handler with the session bound. [The session](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/session.py) and [emitter](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/emitter.py) pair up per connection — one holding state, the other pushing events — so concurrent users are isolated by construction. [The config module](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/config.py) types every setting from a config.toml, from CORS to markdown features.

The third reason is instrumentation and persistence, the two things that make a chatbot a product. [The callbacks system](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/callbacks.py) hooks every lifecycle event, and on top of it sit automatic adapters: [the OpenAI patcher](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/openai/__init__.py) turns SDK calls into streamed steps without any code changes, [the LangChain handler](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/langchain/callbacks.py) translates runs and chains into Steps, and LlamaIndex, MistralAI, and Semantic Kernel each get their module — plus [an MCP client](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/mcp.py) that surfaces Model Context Protocol servers in the UI so tools attach mid-conversation. Persistence is a clean contract in [BaseDataLayer](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/base.py) implemented by [the default layer](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/chainlit_data_layer.py) over [SQLAlchemy](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/sql_alchemy.py), DynamoDB, or Literal AI, with [storage clients](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/storage_clients/azure.py) for S3, Azure, and GCS behind element files. The [React frontend](https://github.com/Chainlit/chainlit/blob/main/frontend/src/App.tsx) with its [Zustand stores](https://github.com/Chainlit/chainlit/blob/main/frontend/src/state/chat.ts) is fully themable and bundled into the package.

Walking the detail diagram, one user message travels the full stack. The browser's [React app](https://github.com/Chainlit/chainlit/blob/main/frontend/src/App.tsx) sends the event to [the socket layer](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/socket.py), which authenticates from [cookies](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/auth/cookie.py) or [JWT](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/auth/jwt.py), creates [a session](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/session.py), and binds it into [the context](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/context.py) your handler reads. The handler appends to [chat_context](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/chat_context.py), maybe mutates [user_session](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/user_session.py), and emits [Messages](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/message.py), [Steps](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/step.py), and [Elements](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/element.py) — each persisted through [the data layer contract](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/base.py) via [the default implementation](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/chainlit_data_layer.py) and its [SQL](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/sql_alchemy.py) or [blob storage](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/data/storage_clients/azure.py) backends. If OpenAI or LangChain is in play, [the instrumentation modules](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/callbacks.py) create Steps invisibly; if MCP servers are configured, [the MCP client](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/mcp.py) manages their tools per session. The server started it all through [the CLI](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/cli/__init__.py) reading [typed config](https://github.com/Chainlit/chainlit/blob/main/backend/chainlit/config.py), and state lands in [the chat store](https://github.com/Chainlit/chainlit/blob/main/frontend/src/state/chat.ts).

## From Install to Your First Chat

Two commands, one file. `pip install chainlit` then `chainlit hello` verifies the whole stack by opening a demo app in your browser. Your own app is a Python file: decorate `async def main(message: cl.Message)` with `@cl.on_message`, reply with `await cl.Message(content="...").send()`, and run `chainlit run demo.py -w` — the `-w` watch mode hot-reloads on save. Streaming replies come from `msg = cl.Message(content=""); await msg.send()` followed by `await msg.stream_token(token)` in your generation loop. Authentication is configuration, not code: set `[auth]` OAuth credentials in config.toml or run with header auth, and every conversation is owned by a persisted user. The data layer activates with a database URL, giving you thread history and resumable sessions; without one, chat state lives in memory. For agent frameworks, the adapters are opt-in imports — `import litellm`, LangChain callback setup, or the OpenAI patcher — and Steps appear in the UI without you writing UI code. Theme everything through config.toml, brand it with custom CSS, and deploy as any ASGI app behind your reverse proxy.

Honest limits: Chainlit gives you a chat-shaped application, and apps that outgrow that shape hit its frame. Multi-tenant production deployments need to think hard about the data layer — the default persistence is straightforward but not sharded, and very high concurrency pushes the single-process Socket.IO model toward multiple workers with sticky sessions. The community-maintained status means release cadence and review bandwidth now depend on volunteer maintainers, and some framework adapters lag their upstream APIs. The frontend ships as a built bundle, so deep UI customization means forking the React app rather than styling alone. Streaming assumes one assistant bubble per handler call, so exotic multi-message flows need manual sequencing. And auto-instrumentation, while magical, adds overhead and can surface steps you would rather hide — every adapter allows filtering, but you have to find the switches. For what it aims at — turning a Python function into a credible chat product in an afternoon — nothing else matches the time-to-demo.
