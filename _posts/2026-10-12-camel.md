There is a question that sounds almost childish until you try to answer it: what happens to agent behavior when you multiply agents the way you multiply model parameters? CAMEL is an open-source community dedicated to finding the scaling laws of agents, and its Python framework is the instrument for that experiment. The README describes a project built by a community of researchers who simulate agent populations at remarkable scale — up to a million agents in companion work — to study their behaviors, capabilities, and risks. What you get after `pip install camel-ai` is deceptively simple: `ChatAgent` wraps your model of choice, a handful of lines create a conversation, and from that seed grow three documented use cases — data generation, task automation, and world simulation. The design principle is called Code-as-Prompt: the code your agents run is itself part of the prompt, blurring the boundary between programming and instructing.

The source tree mirrors that research agenda. The agents package is anchored by one enormous file, nearly six thousand lines, that carries the entire conversational core; specialized siblings for critique, MCP tool servers, repository understanding, and knowledge graphs sit beside it. The societies package holds the multi-agent patterns, from the original two-agent role-playing loop to a Workforce so large it has its own subpackage with task channels, worker types, metrics, and callbacks. The models directory carries one file per provider — OpenAI, Anthropic, Gemini, DeepSeek, Groq, Ollama, vLLM, SGLang, LiteLLM, Together, xAI, Qwen, ZhipuAI and dozens more — behind a factory and a manager. Around these live messages, tasks, memories, prompts, retrievers, verifiers, environments, and a datagen package that distills agent dialogues into chain-of-thought training data. As always in this series, what follows is an educational tour of published source code.

Reading the overview from left to right:

- Everything is grounded in [ChatAgent](https://github.com/camel-ai/camel/blob/master/camel/agents/chat_agent.py), the foundational conversational agent that every higher pattern builds on.
- Conversations flow as [typed messages](https://github.com/camel-ai/camel/blob/master/camel/messages/base.py), with a sibling class for function calls.
- [Prompt templates](https://github.com/camel-ai/camel/blob/master/camel/prompts/prompt_templates.py) carry the research-backed phrasing that shaped the original role-playing experiments.
- [The ModelFactory](https://github.com/camel-ai/camel/blob/master/camel/models/model_factory.py) instantiates one adapter per provider from [a catalog that starts with OpenAI](https://github.com/camel-ai/camel/blob/master/camel/models/openai_model.py).
- [RolePlaying](https://github.com/camel-ai/camel/blob/master/camel/societies/role_playing.py) pairs an AI user with an AI assistant in the society that made the project famous.
- [The Workforce](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/workforce.py) hires agents as workers and coordinates them through [a priority task channel](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/task_channel.py).
- [Browser control](https://github.com/camel-ai/camel/blob/master/camel/toolkits/browser_toolkit.py) headlines [ninety-three toolkit entries](https://github.com/camel-ai/camel/blob/master/camel/toolkits/browser_toolkit.py) the agent can call.
- [Data generation](https://github.com/camel-ai/camel/blob/master/camel/datagen/cot_datagen.py) harvests the resulting dialogues into chain-of-thought training data.

## Why You Need This

The first reason is that CAMEL is the home of role-playing, the technique that started a research movement. The 2023 paper behind this repository showed that two LLMs given opposing roles — an eager task-solver and a mischievous user who keeps inventing new requirements — will happily converse for dozens of turns, and the transcript is a treasure: synthetic dialogue data for instruction tuning, produced without human labeling. [The RolePlaying society](https://github.com/camel-ai/camel/blob/master/camel/societies/role_playing.py) encodes that experiment as reusable machinery at eight hundred lines: it constructs the two ChatAgents from role descriptions drawn from [the prompt template library](https://github.com/camel-ai/camel/blob/master/camel/prompts/prompt_templates.py), drives their turn-taking through a task-specified helper, and exposes a critic variant in [the CriticAgent](https://github.com/camel-ai/camel/blob/master/camel/agents/critic_agent.py) so multiple candidate answers can be scored instead of blindly accepted. Loop termination is its own abstraction in [the terminator base](https://github.com/camel-ai/camel/blob/master/camel/terminators/base.py), which is the kind of care you only see when researchers have run these loops thousands of times and know every way they can run away.

The second reason is the Workforce, which is the most complete open-source take on hierarchical agent teams. [Its main module](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/workforce.py) runs five and a half thousand lines implementing a tree of workers: a coordinator node decomposes an incoming task and assigns pieces to children, children can themselves be Workforces, and results flow back up through callbacks while [a workflow memory manager](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/workflow_memory_manager.py) records what happened for later reflection. The plumbing between workers is [the TaskChannel](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/task_channel.py), a priority queue with explicit states where [tasks](https://github.com/camel-ai/camel/blob/master/camel/tasks/task.py) — objects carrying content, parent links, subtask lists, and failure counts — are posted, claimed, sent back for rework, and archived. A worker is either [a SingleAgentWorker](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/single_agent_worker.py) owning one ChatAgent that loops on its assignment, or [a RolePlayingWorker](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/role_playing_worker.py) that spins up a full two-agent session per task, so the framework's founding pattern literally becomes one worker type among others.

The third reason is the breadth of the model and capability layers, which makes CAMEL a practical hub rather than a laboratory toy. [The models directory](https://github.com/camel-ai/camel/blob/master/camel/models/base_model.py) carries sixty entries, one backend per provider, all implementing a common abstract interface so [the factory](https://github.com/camel-ai/camel/blob/master/camel/models/model_factory.py) needs only a ModelType token and [the manager](https://github.com/camel-ai/camel/blob/master/camel/models/model_manager.py) can route across backends honoring token budgets and priorities — a sensible hedge when a single agent run may consume millions of tokens. The [toolkits package](https://github.com/camel-ai/camel/blob/master/camel/toolkits/browser_toolkit.py) holds ninety-three entries: browser automation, terminal access, code execution, GitHub, Gmail, Google Calendar, Excel, search engines, arXiv, and MCP bridges to external tool servers through [the MCPAgent](https://github.com/camel-ai/camel/blob/master/camel/agents/mcp_agent.py). And because the founding goal is studying agents at scale, the framework ships its own experimental apparatus: [verifiers](https://github.com/camel-ai/camel/blob/master/camel/verifiers/python_verifier.py) that execute generated Python and check it, environments for single-step and multi-step interaction, and [the chain-of-thought generator](https://github.com/camel-ai/camel/blob/master/camel/datagen/cot_datagen.py) alongside self-instruct and source2synth flows in the datagen package.

Walking the detail diagram, the agent layer explains how one class carries so much. [ChatAgent](https://github.com/camel-ai/camel/blob/master/camel/agents/chat_agent.py) is the flagship at five and a half thousand lines, and its size is honest: it owns the model call, the tool-call protocol, structured output, streaming, memory hooks, and step accounting for every downstream pattern. Its conversation currency is [the BaseMessage](https://github.com/camel-ai/camel/blob/master/camel/messages/base.py), a role-and-content wrapper with conversion helpers for every provider's wire format, extended by [FunctionCallingMessage](https://github.com/camel-ai/camel/blob/master/camel/messages/func_message.py) for tool name, arguments, and result. Memory is a layered system: [AgentMemory](https://github.com/camel-ai/camel/blob/master/camel/memories/agent_memories.py) composes [a chat-history block](https://github.com/camel-ai/camel/blob/master/camel/memories/blocks/chat_history_block.py) and [a vector-database block](https://github.com/camel-ai/camel/blob/master/camel/memories/blocks/vectordb_block.py), both producing scored records that [the context creator](https://github.com/camel-ai/camel/blob/master/camel/memories/context_creators/score_based.py) packs into a prompt under a strict token budget — oldest messages drop off not by position but by score. A research flavor sits alongside: [Memanto](https://github.com/camel-ai/camel/blob/master/camel/memories/memanto.py) experiments with human-like recall structures.

The model and society tiers complete the picture. Every backend, from [the OpenAI adapter](https://github.com/camel-ai/camel/blob/master/camel/models/openai_model.py) with its stream and tool handling to [the Ollama adapter](https://github.com/camel-ai/camel/blob/master/camel/models/ollama_model.py) for fully local runs, implements [the BaseModelBackend interface](https://github.com/camel-ai/camel/blob/master/camel/models/base_model.py), and the factory is a clean two-hundred-line map from enum token to class. On the society side, RolePlaying and the Workforce share the same currency of Task objects, which is why tasks, [the channel](https://github.com/camel-ai/camel/blob/master/camel/societies/workforce/task_channel.py), and both worker types form a coherent graph rather than two unrelated subsystems. The capability layer shows the same discipline: [the vector retriever](https://github.com/camel-ai/camel/blob/master/camel/retrievers/vector_retriever.py) does semantic search, [the auto retriever](https://github.com/camel-ai/camel/blob/master/camel/retrievers/auto_retriever.py) wraps it in an end-to-end ingest-and-query flow, [the Python verifier](https://github.com/camel-ai/camel/blob/master/camel/verifiers/python_verifier.py) executes and grades generated code at nearly five hundred lines, and [browser control](https://github.com/camel-ai/camel/blob/master/camel/toolkits/browser_toolkit.py) tops a thousand lines of Playwright integration.

## From Install to Your First Society

The whole path fits in an afternoon. Install with `pip install camel-ai`, or `pip install "camel-ai[all]"` when you want the optional toolkit dependencies. Set one API key — or point at a local Ollama server and use none at all — then create `ChatAgent` with a system message and a model string, and call `step` with your question; the reply arrives as a typed message you can immediately act on. The next rung is `RolePlaying`: give it an assistant role, a user role, and a task prompt, call `init_chat`, and loop `step` pairs that return the user's escalating instructions and the assistant's answers until the terminator fires. The top rung is `Workforce`: construct it with worker nodes describing each agent's competence, hand it one Task, and watch the coordinator split it, workers claim pieces from the channel, and failed tasks bounce back with incremented failure counts until the tree delivers a final answer. Each rung is a dozen or so lines, because the complexity budget was spent inside the framework, not at its edge.

Honest limits: CAMEL is a research framework first, and that cuts both ways. The abstraction surface — societies, terminators, context creators, worker types — is heavier than a simple chat client needs, and the API moves fast enough that code copied from older tutorials can break between minor versions. The README's most ambitious claims, such as million-agent world simulation, live partly in the companion oasis repository rather than this one, so read this codebase as the framework core, not the whole research program. Error messages when a model key or toolkit dependency is missing can be terse, and the sheer number of provider backends means the less popular ones receive thinner test coverage than OpenAI and Anthropic. None of that dims the core value: for role-playing data generation, hierarchical workforces, or reproducible multi-agent experiments, this is the codebase the literature keeps coming back to.
