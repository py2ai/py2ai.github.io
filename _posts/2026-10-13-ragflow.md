Most retrieval-augmented generation projects treat documents as text to be split; RAGFlow was built on the conviction that the hard part happens before the first embedding call. Scanned PDFs, multi-column papers, tables spanning pages, contracts with stamps — a naive text extractor mangles all of them, and no amount of clever retrieval fixes garbage chunks. So RAGFlow invested where others didn't: an OCR stack that detects and reads text visually, a layout analyzer that understands columns and reading order, and template-aware chunking that respects document structure. Apache-2.0-licensed and developed by InfiniFlow, it has grown into one of the most-starred RAG engines on GitHub, and its current main branch tells a second story: the Python backend has been rewritten in Go, with compiled services for ingestion, search, and agents, while the Python SDK and the React UI stay as the friendly outer shell — a production systems project, not a research demo.

The architecture splits into four planes that meet at the HTTP router. The document plane is the deepest: an ingestion service in `internal/ingestion/` queues every upload as a tracked task, DeepDoc's ONNX sessions read pages like a human would, format parsers normalize DOCX and CSV and audio, a delimiter-aware chunker splits the text, and an embedder batches the results into vectors. The index plane abstracts search behind one interface with Elasticsearch, Infinity, OceanBase and more behind it. The agent plane runs visual workflows — a canvas of components from a Begin entry point through LLM calls, categorizers, and browsers — plus a dedicated agentic RAG loop that iterates searches and cites evidence. The API plane binds it all: one Go binary, a REST router, an MCP surface, and metadata in a DAO layer. As always in this series, what follows is an educational tour of published source code.

Reading the overview from left to right:

- [The React web app](https://github.com/infiniflow/ragflow/blob/main/web/src) covers datasets, chats, files and agent builders in a Vite-built UI.
- [The Python SDK](https://github.com/infiniflow/ragflow/blob/main/sdk/python/ragflow_sdk/ragflow.py) mirrors the REST surface for programmatic use.
- [The RAGFlow server](https://github.com/infiniflow/ragflow/blob/main/cmd/ragflow_server.go) wires config, engines, storage and services into one binary.
- [The HTTP router](https://github.com/infiniflow/ragflow/blob/main/internal/router/router.go) registers every route for datasets, documents, chunks, chats and agents.
- [The ingestion service](https://github.com/infiniflow/ragflow/blob/main/internal/ingestion/service/ingestion_service.go) executes document tasks with heartbeats and progress tracking.
- [The OCR sessions](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/session.go) pool ONNX inference for detection and recognition models.
- [The chunker](https://github.com/infiniflow/ragflow/blob/main/internal/parser/chunk/split.go) splits parsed text under delimiter and size rules.
- [The search engine interface](https://github.com/infiniflow/ragflow/blob/main/internal/engine/engine.go) hides Elasticsearch, Infinity and other backends behind one contract.

## Why You Need This

The first reason is DeepDoc, the document-understanding stack that justifies RAGFlow's reputation. Under `internal/deepdoc/`, [the ONNX session pool](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/session.go) loads computer-vision models once and shares them across workers, with explicit memory management for weights. [The text detector](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/det.go) runs DBNet-style segmentation to find text boxes on page images; [the recognizer](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/ocr_rec.go) reads each cropped box with a CRNN; [the table structure recognizer](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/tsr.go) recovers rows and columns from table images so cells survive as cells instead of soup. Above the models, [the PDF layout analyzer](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/parser/pdf/layout/layout.go) — nearly eight hundred lines — sorts characters into lines, lines into columns, and regions into reading order, handling the cross-page tables and floating captions that defeat naive extractors. Reading this half teaches what "deep document understanding" actually costs: real vision models, real geometry, and real engineering around ONNX runtime sessions.

The second reason is the document path, which shows what a production ingestion system looks like when written by people who have been burned by batch scripts. [The ingestion service](https://github.com/infiniflow/ragflow/blob/main/internal/ingestion/service/ingestion_service.go) — twelve hundred lines — owns the task lifecycle: acknowledgements, heartbeats, progress sinks, redelivery counters, and convergence tests that verify a document reaches a terminal state. [Format parsers](https://github.com/infiniflow/ragflow/blob/main/internal/parser/parser) normalize DOCX, CSV, audio, email and more into text plus structure; [the chunker](https://github.com/infiniflow/ragflow/blob/main/internal/parser/chunk/split.go) applies preprocessing, delimiter-aware splitting, and postprocessing with test coverage for each stage; and [the embedder](https://github.com/infiniflow/ragflow/blob/main/internal/ingestion/task/embedder.go) batches chunks into embedding calls under [explicit token limits](https://github.com/infiniflow/ragflow/blob/main/internal/tokenizer/tokenizer.go). Originals and derivatives live in [the storage factory](https://github.com/infiniflow/ragflow/blob/main/internal/storage/storage_factory.go), which selects MinIO, S3, OSS, GCS or in-memory blobs from config. It is a complete curriculum in robust data flow: every failure mode you have hit in a document importer has a named, tested mechanism here.

The third reason is the agent and retrieval plane, which turns the corpus from a search box into a reasoning substrate. The workflow side implements a canvas of typed components: [the base contract](https://github.com/infiniflow/ragflow/blob/main/internal/agent/component/base.go) defines inputs, outputs and invocation, [the LLM agent component](https://github.com/infiniflow/ragflow/blob/main/internal/agent/component/agent.go) — the largest at sixteen hundred lines — adds tool calling and streaming, and neighbors cover [workflow entry](https://github.com/infiniflow/ragflow/blob/main/internal/agent/component/begin.go), [intent-based branching](https://github.com/infiniflow/ragflow/blob/main/internal/agent/component/categorize.go), and [headless browsing](https://github.com/infiniflow/ragflow/blob/main/internal/agent/component/browser.go). [The runtime](https://github.com/infiniflow/ragflow/blob/main/internal/agent/runtime/component.go) executes the graph with shared context and a retrieval bridge, while [the tool registry](https://github.com/infiniflow/ragflow/blob/main/internal/agent/tool/registry.go) wires dozens of callable tools from [corpus search](https://github.com/infiniflow/ragflow/blob/main/internal/agent/tool/agentic_search.go) to [sandboxed code execution](https://github.com/infiniflow/ragflow/blob/main/internal/agent/tool/code_exec.go). The retrieval side goes further: [the agentic RAG loop](https://github.com/infiniflow/ragflow/blob/main/internal/agentic_rag/agent.go) plans multi-step searches, tracks what it has found in an evidence registry, and attaches citations — with prompt templates for queries, keywords, and citation discipline versioned as markdown in `rag/prompts/`.

Walking the detail diagram, one document is traceable end to end. An upload lands on [the router](https://github.com/infiniflow/ragflow/blob/main/internal/router/router.go), which queues a task in [the ingestion service](https://github.com/infiniflow/ragflow/blob/main/internal/ingestion/service/ingestion_service.go) and stores the original file in [object storage](https://github.com/infiniflow/ragflow/blob/main/internal/storage/storage_factory.go). The worker invokes the right reader from [the format parsers](https://github.com/infiniflow/ragflow/blob/main/internal/parser/parser); a scanned PDF goes through [the OCR session pool](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/session.go), where [the detector](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/det.go) finds text boxes and [the recognizer](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/native/ocr_rec.go) reads them, and [the layout analyzer](https://github.com/infiniflow/ragflow/blob/main/internal/deepdoc/parser/pdf/layout/layout.go) restores reading order. The text flows into [the chunker](https://github.com/infiniflow/ragflow/blob/main/internal/parser/chunk/split.go), then [the embedder](https://github.com/infiniflow/ragflow/blob/main/internal/ingestion/task/embedder.go) vectorizes the chunks and writes them into [the search engine](https://github.com/infiniflow/ragflow/blob/main/internal/engine/engine.go) — concretely [the Elasticsearch client](https://github.com/infiniflow/ragflow/blob/main/internal/engine/elasticsearch/client.go) or [the Infinity client](https://github.com/infiniflow/ragflow/blob/main/internal/engine/infinity/client.go), speaking the shared schema of [the engine types](https://github.com/infiniflow/ragflow/blob/main/internal/engine/types/types.go). Progress reports flow back to the UI the whole way, so the system can show exactly which document is stuck and why.

The second walkthrough is a question rather than a file. A user asks something in chat; the router dispatches to the conversation service; and when agentic retrieval is enabled, [the agentic RAG agent](https://github.com/infiniflow/ragflow/blob/main/internal/agentic_rag/agent.go) begins its loop — generate query variants, search, read the hits, decide whether the evidence suffices, and either iterate or answer with citations. Each step consumes templates from [the prompt library](https://github.com/infiniflow/ragflow/blob/main/rag/prompts): query generation, keyword extraction, cross-language rewriting, citation forcing. The same corpus is reachable from the agent side through [the search tool](https://github.com/infiniflow/ragflow/blob/main/internal/agent/tool/agentic_search.go) inside a canvas workflow — the design lesson of the whole plane: one retrieval substrate, two consumption styles, scripted workflow graphs for predictable processes and an autonomous loop for open questions. The MCP surface in `internal/mcp/` and [the Python SDK](https://github.com/infiniflow/ragflow/blob/main/sdk/python/ragflow_sdk/ragflow.py) make the same corpus reachable from third-party tools and scripts.

## From Install to Your First Chat

The supported route is Docker Compose: clone the repo, edit `docker/.env` to set your LLM provider key, and `docker compose -f docker/docker-compose.yml up -d` brings up the server, Elasticsearch or Infinity, MinIO, Redis and MySQL. The web UI listens on port 80; sign up, create a knowledge base, and drop in PDFs — the document plane takes over, showing per-file parsing progress as it runs. To use the corpus from code, `pip install ragflow-sdk`, create a client with your base URL and API key, and the SDK's `RAGFlow` object exposes datasets, chats, and agents as plain Python objects. Agent building happens in the UI canvas — drag an LLM component, wire it to a retrieval component, add a categorizer for routing — and the resulting graph runs from the API exactly like the built-in chat. For development, the Go services build with standard tooling and the frontend with `npm run build`.

Honest limits: the Go rewrite is recent enough that much of the documentation, and most third-party tutorials, still describe the older Python architecture, so file references in guides can drift from the tree you are reading. The full stack — OCR models, search engine, vector database, MySQL, Redis, MinIO — is heavy for a laptop, and the DeepDoc vision models add meaningful startup cost and memory. Agentic RAG multiplies LLM calls per question, which is powerful and expensive at the same time. And the dual heritage means some behaviors are configured in YAML, some in the UI, and some in code. None of that changes the verdict: RAGFlow is the deepest open-source treatment of the document side of RAG, and its source is the best available map of what production ingestion actually requires.
